# Омонимичные корни в задании 9

Подготовлен точечный скрипт `app.scripts.add_task9_homonymy`. Изменения на сайт не применялись.

Дополнение теперь также доступно в форме через **Теория → Чередующиеся корни → Изменения по коду → Пример: Омонимичные корни · задание 9**. Это предпочтительный способ просмотра, ручной правки и применения; см. `docs/theory-edit-packages.md`. Отдельный скрипт остаётся альтернативой.

## Что изменится

В существующей теме **«Чередующиеся корни»** (`legacy-theory-9`), привязанной к заданию 9:

1. После зелёного правила появятся предупреждение об омонимии, сравнение **загорать / горевать / гористый** и пояснение о похожих буквосочетаниях.
2. После каждой из четырёх групп чередований появится закрытый по умолчанию подраздел **«Значения корней и омонимы…»**. Внутри — двухколоночная таблица: корень, его значение и примеры. Для группы по значению — сравнение мак/мок и равн/ровн.
3. В пояснение к суффиксу -а- добавлены пары **сжать — сжимать, начать — начинать, понять — понимать, принять — принимать**.

Существующие таблицы, исключения, авторские заметки, ссылки на практику, вложенность и ручные правки сохраняются. Используется уже существующий тип блока `section`; менять интерфейс и схему БД не требуется. Метки «＋ Добавлено» есть только в демонстрации, в учебную теорию они не записываются.

## Уточнения к исходному тексту

- Вместо категоричного «главная ловушка» — конкретное объяснение ошибки: совпадения букв недостаточно, нужно учитывать значение.
- Корень **лаг/лож** оставлен в существующей группе по согласной; в раскрытии объяснён и ориентир на суффикс -а-.
- **Утварь** названа исключением, а не омонимом.
- **Ложка, горизонт, роскошь** отделены от строгой омонимии: похожие буквы могут входить в другой корень.
- Для **-ин-/-им-** не вводится искусственное общее значение. Даются пары родственных слов и правило суффикса.
- **Плав/плов** пояснено как особая группа с исключениями, без механического выбора по ударению.
- Значения расширены там, где буквальное толкование мешало бы: **блистательный**, **склоняться к решению**, **растирать**.

## Проверка без базы данных

Из каталога `backend`:

```sh
python -m app.scripts.add_task9_homonymy --preview-json task9-preview.json
python -m unittest discover -s tests -p 'test_task9_homonymy*.py' -v
```

JSON содержит «до» и «после» на основе текста из репозитория. Это не выгрузка с рабочего сайта. Встроенный предпросмотр в чате собран из этих же данных. На рабочей базе скрипт использует текущую опубликованную версию документа и добавляет пояснения к ней.

## Применение

Сначала установить файлы скрипта и модуля содержимого на сервер обычным способом. В командах ниже заменить `COURSE_CODE` реальным кодом версии курса. Код обязателен; скрипт не выбирает произвольный курс.

Проверить план на текущей базе, без записи:

```sh
docker compose exec backend python -m app.scripts.add_task9_homonymy --course-version COURSE_CODE
```

Создать черновик новой версии:

```sh
docker compose exec backend python -m app.scripts.add_task9_homonymy --course-version COURSE_CODE --execute
```

Просмотреть его в редакторе темы «Чередующиеся корни» и опубликовать штатной кнопкой. Если нужен запуск с немедленной публикацией вместо создания черновика, предусмотрено:

```sh
docker compose exec backend python -m app.scripts.add_task9_homonymy --course-version COURSE_CODE --execute --publish
```

Команды создания черновика и немедленной публикации — альтернативы. Если уже существует черновик, скрипт останавливается, чтобы сохранить его правки; сначала завершить работу с ним в редакторе. Ранее опубликованная версия сохраняется в истории; скрипт выводит её ID.

Всё выполняется одной транзакцией. При отсутствующих/дублирующихся заголовках или повреждённой вложенности запись не завершается. Повторное применение к уже дополненной публикации ничего не добавляет. Частично сохранившееся дополнение требует проверки, а не автоматического дублирования. Запуск общего `publish_curated_theory` для этого дополнения не нужен.

## Границы проверки

Выполнено 10 проверок: сохранение исходных блоков и вложенности, повторный запуск, частичное дополнение, смещение опорных заголовков, повреждённые родительские связи, порядок ссылки на практику, режим без записи, создание черновика, публикация и защита существующего черновика. Проверки создания версий используют модели приложения и имитацию сессии БД; реальная база не изменялась. Предпросмотр проверен в браузере при ширине 320, 390 и 736 пикселей, включая раскрытие всех подразделов и переключение «До / После».
