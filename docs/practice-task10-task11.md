# Практика заданий 10 и 11

Банк подготовлен из актуальной выгрузки `/api/v2/admin/exports/practice`. До изменений: 342 упражнения, из них 312 без объяснения. Новая версия: **2060 карточек**, 10 тематических наборов и две смешанные практики. Содержимое публикуется владельцем через форму после сравнения.

В смешанной практике 10-го — **1029** уникальных слов, 11-го — **994**. Внутри темы слова и маски не повторяются. Одно слово может встречаться в разных тематических наборах с разными орфограммами: например, «разыскать» для А/О и для И/Ы. Смешанный набор берёт одну карточку на слово. Объём малых тем не увеличивается падежными формами и одинаковыми словами с разными вводными фразами.

## Источники и проверка

- [Навигатор ФИПИ, орфография, 2026](https://doc.fipi.ru/navigator-podgotovki/navigator-ege/2026/ru-5-orfografija.pdf): состав проверяемых орфограмм и обязательные примеры.
- [Академос ИРЯ РАН](https://orfo.ruslang.ru/search): точное написание каждого прошедшего словарную проверку слова, с различением Е/Ё.
- [Бешенкова, Иванова. Аспектное описание русской орфографии, ИРЯ РАН](https://orfo.ruslang.ru/docs/biblio/beshenkova-ivanova-2018.pdf): правила и исключения.
- [Официальное объяснение Грамоты.ру](https://gramota.ru/poisk?mode=all&query=%D0%B0%D0%BB%D0%B5%D0%B1%D0%B0%D1%80%D0%B4%D1%89%D0%B8%D0%BA): пример «асфальтщик», не представленный отдельным заголовком в Академосе.

Маски и пояснения составлены для Пумрус; это тренировочный банк, а не выгрузка официальных заданий ФИПИ. У 2056 карточек подтверждение точным заголовком Академоса; у трёх («дословно», «достоин», «лишён») — явным примером из навигатора ФИПИ; у «асфальтщик» — официальным правилом Грамоты.ру.

Файл `backend/app/scripts/data/task10_11_dictionary_evidence.json` хранит URL, дату, нормализованные заголовки и SHA-256 полученного документа. Запись `not_found` означает отсутствие точного словарного заголовка, а не признание слова неправильным. Такие кандидаты в банк не попадают без другого явного официального подтверждения. Полные тексты словарных определений в банк не копируются.

Повторная проверка возобновляется с сохранённого места:

```powershell
python -m app.scripts.verify_task10_11_dictionary app/scripts/data/task10_11_dictionary_evidence.json --workers 2
```

Необязательные `--fipi-pdf` и `--gramota-suffix-html` принимают сохранённые официальные документы для трёх примеров ФИПИ и исключения «асфальтщик». Для PDF нужен `pypdf`; он не требуется при обычной работе сайта.

## Что исправляется

- Слова распределяются по десяти текущим темам каталога. Например, «сестрицын» относится к суффиксам прилагательных, «простаивать» — к глаголам, «въявь» — к разделительному Ъ задания 10.
- Смысловые пары получают контекст: «претворить замысел в жизнь / притворить дверь», «обезводеть в засуху / обезводить раствор», «масляный насос / масленый блин».
- Е/Ё сохраняются различными буквами; исправленные написания не заменяют Ё на Е.
- Пояснение задаётся и для правильного, и для неправильного ответа. В тренажёре его можно раскрыть кнопкой «Почему так?»; источники видны после ответа.
- При восстановлении выполненного упражнения слово показывается целиком, даже если старый ответ сохранён без массива букв.

## Применение через форму

Сначала обновить frontend и backend; миграция БД не нужна.

1. Открыть **Практика → Обновить банк по JSON**.
2. Нажать **Открыть JSON** и выбрать `practice-task10-task11.json`. Пакет около 4 МБ, поэтому открытие файла удобнее вставки из буфера.
3. Сравнить объёмы и карточки «До → После». Фильтры находят тему, слово или правило. Раскрыть список старых слов/форм, не входящих в новый активный банк.
4. При необходимости изменить текст в `after.topics[].cards`. `before` и `base` оставлять неизменными. Изменение проверяемого слова требует подтверждения нового написания, а не только замены ответа.
5. Нажать **Проверить пакет**, затем **Применить изменения**.

Формат: `pumrus.practice-edit`, `schemaVersion: 1`. Это отдельный формат практики; окно изменений теории его не принимает. `base.fingerprint` фиксирует публикации, карточки, настройки и состав исходных наборов заданий 10 и 11. После редактирования JSON серверная проверка требуется снова.

API:

- `POST /api/v2/admin/practice-edit/preview` — проверка без записи.
- `POST /api/v2/admin/practice-edit/apply` — повторная проверка базы и публикация одной транзакцией.

## История и сохранность данных

Совпадающие упражнения по возможности используют прежние ID; исправления получают новую версию. Старые версии и результаты попыток не удаляются. Наборы и упражнения, используемые другими заданиями, защищены от изменения. Старые карточки вне утверждённого банка убираются из активных наборов с сохранением истории.

ID существующих основных наборов и тем сохраняются; недостающие тематические наборы создаются. Настройки доступа, размера сессии, страниц и ручного демо сохраняются. Автоматическое демо наполняется заново. Привязки упражнений к темам и заданиям заменяются на проверенные. Готовая сессия продолжает использовать свои старые версии; новый банк появляется в новых сессиях.

Повторное применение старого пакета отклоняется по отпечатку. Изменения владельца после экспорта и существующие черновики упражнений также блокируют применение. Общая старая команда расширения практики не перезаписывает уже опубликованный проверенный банк 10/11.

## Подготовка нового пакета

```powershell
python -m app.scripts.task10_11_revision live-practice-export.json practice-task10-task11.json
```

Команда читает выгрузку и подтверждения, проверяет маски, непустые пояснения, уникальность, допустимые источники и привязки, затем записывает JSON. Подключения к БД и публикации нет. CSV с полным списком слов и источников удобно использовать для редакторской проверки.

Проверено: полный банк, защита исходной версии, отсутствие записи при предпросмотре/конфликте, сохранение ID и версий при публикации на записывающем макете сессии, перенос неверных связей между заданиями, прежние проверки задания 9. В браузере проверены загрузка полного JSON, фильтры, повторное открытие файла, ошибки JSON, конфликт версий, применение на имитации API, раскрытие пояснений и экраны 320/390 пикселей. Тесты, требующие реальной PostgreSQL, в локальной среде пропущены.
