# PUMRUS Frontend

Фронтенд PUMRUS — это одностраничное React‑приложение, заточенное под запуск как Telegram WebApp и работу с вашим DDD‑бекендом теории и заданий через REST API.

## Архитектура

Фронтенд логически делится на три крупные подсистемы:

- **Пользовательское приложение** (`App.jsx` + `components.jsx`), где ученик выбирает предмет, открывает теорию и запускает тренажёры.[1][2]
- **Админ‑форма для редактирования теории** (`FormApp.jsx` и компоненты в `components/`), которая управляет сущностями Theory/Blocks/TaskTheory через те же API, что описаны в бекенде.[3][4][5][6]
- **Модуль тренажёров** (стресс, приставки, словарные, слитно/раздельно) с переиспользуемыми хуками и пагинацией.[7][8][9][10][11]

Общий дизайн и темы оформлены через CSS‑токены в `static.css`, поверх которых настраиваются отдельные слои стилей для основного приложения, формы и тренажёров.[12][13][14][15][16]

## Точки входа и окружение

### main.jsx — пользовательское приложение

`main.jsx` использует React 18 `createRoot` и монтирует `App` в элемент `#root`, предназначенный для основного пользовательского интерфейса (Telegram WebApp).

```js
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
// import './index.css'
import App from './App.jsx'

createRoot(document.getElementById('root')).render(
  // <StrictMode><App /></StrictMode> — в реальном файле
)
```



### index.jsx — админ‑форма

Второй entry‑point `index.jsx` импортирует `FormApp` и также создаёт корень React в `#root`, рассчитанный на другое HTML‑полотно (`form.html`).[18][3]

```js
import React from "react";
import ReactDOM from "react-dom/client";
import FormApp from "./FormApp";

const rootElement = document.getElementById("root");

if (rootElement) {
  const root = ReactDOM.createRoot(rootElement);
  root.render(/* <FormApp /> */);
} else {
  console.error('Не найден элемент с id="root" для FormApp');
}
```



### HTML‑оболочки

В репозитории присутствуют `index.html` и `form.html`, каждый из которых предоставляет `div#root` для соответствующего бандла.[19][20]

## Темы, дизайн‑система и CSS

### Базовые токены темы (`static.css`)

`static.css` задаёт CSS‑переменные для типографики, цветов, скруглений и иконограмм навигации, формируя ядро тёмной темы и её светлого варианта.[14]

Ключевые токены:

- Шрифты: `--chapter-text` (заголовки, крупный текст), `--text-font` (основной текст).[14]
- Цвета для тёмной темы: `--main-color` (фон приложения), `--block-color` (фон карточек), `--text-color`, `--active-color` (акцент), а также `--rule-color`, `--important-color`, `--exception-color` для разных callout‑типов теории.[14]
- Аналогичные значения переопределяются для светлой темы при наличии класса `body.theme--light`.[14]
- Иконки навигации через переменные: `--go-icon`, `--back-icon`, `--close-icon`, `--open-group-icon`, `--close-group-icon`.[14]

### Общий layout (`General.css`)

`General.css` отвечает за каркас основного приложения (`App.jsx`): вертикальный скролл, шапку с аватаркой и текстом, выбор предмета и переключатель между теориями и задачами.[13]

Основные блоки:

- `.main` — полноэкранный контейнер с вертикальным скроллом и анимацией плавного появления/исчезновения.[13]
- `.mainTitle` + `__picture`/`__title`/`__text` — приветственный блок с круглой картинкой (`/picture.jpg`), заголовком и описанием.[13]
- `.subject__block` — контейнер для выбора предмета.
- `.theoryChoose` и модификаторы `__task--active/hidden`, `__theme--active/hidden` — таб‑переключатель между выбором тем и заданий.[13]
- `.option` и её элементы — визуальный вариант кнопки выбора предмета/темы с круглым чек‑индикатором слева.[13]
- `.elementBlock` и модификаторы `--small/--big` — контейнер для списка теорий/заданий, высота которого зависит от выбранного режима.[13]
- `.back-to-subjects-button` — плавающая кнопка «назад к предметам» в левом верхнем углу.[13]

### Компонентные стили (`components.css`)

`components.css` описывает визуальное поведение карточек теории, попапа, элементов заданий и аккордеонов.[12]

Ключевые блоки:

- `.element` — базовая интерактивная карточка с левым акцент‑баром, hover‑эффектом и состоянием `--opened`, `--toggle`, `--loading`.[12]
- `.task-theory-block` и `.task-element-block` — контейнеры для блоков теории, привязанных к заданиям, с анимациями `fadeIn`/`slideDown`.[12]
- `.popup` + `__header`/`__button`/`__title`/`__content` — полноэкранный попап с заголовком, крестиком, плавными анимациями появления и скрытия.[12]
- `.theory--visual`, `.theory__text`, `.theory__subtitle`, `.theory__link`, `.theory__rule` — текстовые элементы для визуализации дерева `TheoryBlock` по типам (`title`, `subtitle`, `rule`, `example`, `exception`, `important`, `text`, `svg`, `group`, `link`).[12]
- `.theory--group`/`__header`/`.theory--children` — аккордеон для вложенных «групп» теории с поворачивающейся стрелкой и подсветкой выбранного состояния.[12]
- `.theory__example--fieldset--rule/important/exception` — callout‑карточки для правила, важного замечания и исключения.[12]

Анимации (`@keyframes fadeIn`, `slideDown`, `popupFadeIn`, `spin`, `pulse`) переиспользуются как в попапах, так и в блоках теории.[12]

### Стили формы (`form.css`)

`form.css` оформляет админ‑панель редактуры теории:[15]

- `.form-root` — полноэкранный контейнер с тёмным фоном и вертикальной раскладкой.[15]
- `.form-header` + `.form-tabs` — заголовок формы и табы «Теория / Задания».[3][15]
- `.form-top` — панель выбора предмета, типов теории и конкретной теории (использует `SubjectSelect`, `TheoryTypeSelect`, `TheorySelect`).[3][15]
- `.form-main` — двухколоночный layout: слева дерево блоков (`BlocksTree`), справа редактор (`BlockEditor`).[4][5][15]
- `.form-tree__item` с модификаторами `--active`, кнопками `__add`, `__move-btn` — интерактивный список блоков с подсветкой текущего и стрелками перестановки.[15]
- `.form-editor__field`/`--textarea`, `.form-editor__actions` — поля и кнопки редактора блока, включая красную кнопку удаления и зелёную «Сохранить теорию».[3][15]

### Стили тренажёров (`trainers.css`)

`trainers.css` отвечает за единый визуальный стиль всех тренажёров:[16]

- `.trainer-container`, `.trainer-controls`, `.trainer-button` — общий контейнер и панель управления (сброс, ошибки, выход).[21][16]
- `.trainer-page-nav` и `.trainer-page-indicator` — навигация по страницам из `useTrainerPagination`.[22][16]
- `.trainer-stats` — карточка статистики (сколько слов/букв отработано, точность).[16][21]
- Специфические элементы: `.trainer-word-display`, `.trainer-vowel-slot` (стресс), `.trainer-word-input` и `.trainer-letter` (приставки/словари), `.trainer-popup` и `trainer-mistake-word` для попапов с ошибками.[9][23][7][16]

### Сброс и базовые стили (`index.css`)

`index.css` содержит минимальный reset, адаптированный под Telegram WebApp и Vite:[24]

- Сброс `box-sizing` и шрифтов для `:root`.
- Базовый фон `body` через `--main-color`.
- Сброс нативных стилей кнопок и ссылок (`button { all: unset; }`, `a { color: inherit; }`).[24]

## Пользовательское приложение (`App.jsx` + общие компоненты)

### App.jsx — основной сценарий ученика

`App.jsx` подключает `General.css`, компонент `Chapter`, общие UI‑компоненты (`Element`, `TaskElement`, `Popup`) и четыре тренажёра (Stress/Prefix/Dictionary/Spelling).[2][8][23][1][7][9][13]

В файле определены:

- Вспомогательные функции `saveInfo`/`getInfo`, которые сохраняют настройки пользователя в `localStorage`.[1]
- Константа `TRAINERS` — список доступных тренажёров с `id`, подписью и React‑компонентом.[8][23][7][9][1]
- Компонент `Option`, представляющий кнопку выбора (предмет, теория и т.п.) с локальным флагом `isChosen`.[1][13]

Основной компонент `App` (по имени файла) собирает:

- Шапку (`.mainTitle`) с картинкой и описанием курса.[13]
- Список предметов в виде `Chapter`‑карточек (например, русский язык / информатика).[25]
- Блок выбора режима «Теория / Задания» (`.theoryChoose`).[13]
- Список `Element`/`TaskElement`, которые при нажатии открывают попап с теорией или списком задач.[2]
- Хук/состояние для активации тренажёров из списка `TRAINERS`.[23][7][8][9][1]

### Общие компоненты (`components.jsx`)

`components.jsx` реализует ключевые строительные блоки пользовательского интерфейса:[2]

- **`Element`** — элемент списка теорий. Хранит локальный флаг загрузки, по клику делает `fetch('/api/theory/get_theory/{id}')`, передаёт загруженные `name` и `blocks` наверх (`setContent`) и открывает попап (`setPopup(true)`).[2]
- **`TaskElement`** (по структуре файла) — аналог для элементов, связанных с заданиями; отображает более сложный блок с группами теорий, используя CSS‑классы `.task-element-block`.[2][12]
- **`Popup`** — компонент полноэкранного попапа, использующий разметку и стили из `.popup`/`__header`/`__content` в `components.css`.[2][12]

Таким образом, пользовательский слой работает по схеме:

> Клик по Element → `fetch /api/theory/get_theory/{id}` → отображение дерева блоков внутри стилизованного попапа.

[2][12]

### Chapter — карточки разделов

Компонент `Chapter` (`chapter.jsx`) — это стилизованная карточка с текстом и иконкой «вперёд/назад», использующая токены `--go-icon` и `--back-icon`.[17][25]

- В режиме `subject` отображает имя предмета по центру.[25]
- В обычном режиме показывает текст слева и стрелку справа (`chapter__icon--open`/`--close`).[17][25]

## Админ‑форма редактирования теории (`FormApp.jsx` и компоненты)

### Общая идея

`FormApp.jsx` — это отдельное приложение/страница для контент‑менеджера, которое позволяет:

- Выбирать предмет и теорию.
- Создавать/редактировать/удалять теории и их блоки (`TheoryBlock`) с иерархией.
- Управлять типами теорий (справочник `TheoryType`).
- Настраивать группы заданий и привязку заданий к теориям через `TasksTheoryEditor`.

Все операции выполняются через REST‑методы бекенда, описанные в вашей backend‑документации.[6][3]

### Состояние и загрузка данных

`FormApp` хранит в `useState`:

- `subjects` — список предметов с их типами теории, загружается через `GET /api/theory/all_theory_dop_info`.[3]
- `selectedSubjectId`, `theories`, `selectedTheoryId`, `theory` — выбор предмета и текущей теории с блоками.[3]
- `selectedBlockId`, `blockDraft` — выбранный блок и его черновик для редактирования.[3]
- `selectedTheoryTypeIds` — активные типы теории для текущей записи.[3]
- `isCreatingTheory`, `newTheoryName` — состояние создания новой теории.[3]
- `activeTab` — переключатель между вкладками "theory" и "tasks" (редактирование теории или групп/заданий).[15][3]

Сайд‑эффекты:

1. При монтировании: загрузка справочников `all_theory_dop_info`.[3]
2. При выборе предмета: `GET /api/theory/all_theory_for_subject/{subjectId}`, обновление списка теорий и выбранных типов.[3]
3. При смене теории: `GET /api/theory/get_theory/{id}`, загрузка теории с блоками.[3]
4. При смене `selectedBlockId`: поиск блока в плоском списке и заполнение `blockDraft`.[3]

Для работы с переносами строк использованы две функции конвертации:

- `convertBlocksFromAPI` — заменяет `"\\n"` на реальные переводы строки `"\n"` в `content` всех блоков и их детей, чтобы удобно редактировать текст.[3]
- `convertBlockForAPI` — обратная замена `"\n"` на `"\\n"` перед отправкой в API, синхронизируясь с доменной моделью на бекенде.[3]

### Работа с блоками теории

Главная логика по блокам:

- `flattenBlocks` — рекурсивно превращает дерево блоков в плоский массив (используется для поиска по `id`).[3]
- `collectAllChildIds` — собирает `id` всех детей, чтобы выделить только настоящие корни дерева.[3]
- `collectChildrenForParent` — возвращает список детей по `parentId` (или корней, если `parentId == null`).[3]
- `createBlockAt(theoryId, parentId)` — создаёт новый блок в корне или внутри группы:
  - Находит существующих «сиблингов».
  - Вычисляет новый `order` как последний + 1.
  - Делает `POST /api/theory/{theoryId}/blocks` с полями `type`, `content`, `parent_id`, `order`.
  - Сразу перезагружает теорию через `GET /api/theory/get_theory/{theoryId}` и выделяет последний по `id` блок как активный.[3]

Редактирование/удаление:

- `handleSaveBlock` — отправляет обновлённый `blockDraft` на `PUT /api/theory/blocks/{blockId}`, затем повторно загружает теорию с конвертацией переносов.[3]
- `handleDeleteBlock` — спрашивает подтверждение, вызывает `DELETE /api/theory/blocks/{blockId}`, сбрасывает выбор и черновик.[3]

Перестановка блоков:

- `handleMoveBlock(blockId, direction)`:
  - Вычисляет список «сиблингов» для этого блока.
  - Находит соседа выше/ниже в сортировке по `order`.
  - Локально меняет их `order` и отправляет два `PUT` подряд для обоих, затем перезагружает теорию.[3]

Таким образом, фронтенд полностью уважает доменную логику порядка блоков, реализованную в бекенде.

### Создание и обновление теорий

- `handleStartCreateTheory` — очищает состояние и включает режим создания.[3]
- `handleSaveNewTheory` — делает `POST /api/theory/` с `name`, `subject` и массивом `type_ids`, затем добавляет созданную теорию в локальный список и переключается на неё.[3]
- `handleUpdateTheoryTypes` — при смене выбранных типов делает `PUT /api/theory/{id}` c `type_ids` и синхронизирует как `theory`, так и `theories` (для списка слева/справа).[3]

### Вспомогательные компоненты формы

- **`SubjectSelect`** — селект выбора предмета из `subjects`, принимает `selectedSubjectId` и `onChange`.[26][3]
- **`TheorySelect`** — селект теории; рендерит опции из `theories`, поддерживает выбор `null` и кнопку «Создать новую теорию».[27][3]
- **`TheoryTypeSelect`** — набор «чипов» типов теории; клик по типу добавляет/удаляет `id` из `selectedTheoryTypeIds`.[28][3]
- **`BlocksTree`** — иерархическое дерево блоков, отображающее `order`, `type`, укороченный `content` и кнопки перемещения/добавления.[4][15]
- **`BlockEditor`** — форма редактирования выбранного блока:
  - Список типов (`BLOCK_TYPES`) с русскими подписями.
  - Textarea для `content` с возможностью оборачивать выделенный текст в `**` (жирный) по клику на кнопку.
  - Все изменения делаются через `onChange(prev => ({ ...prev, field: value }))` без потери переносов.[5][15]

### Редактор групп заданий и связей (`TasksTheoryEditor`)

`TasksTheoryEditor` работает в отдельной вкладке "tasks" формы и управляет сущностями TaskTheoryGroup/TaskTheory и связями `task_theory2theory`:[6][15]

- При смене `subjectId` загружает все группы и задания через `GET /api/theory/get_tasks_theory_for_subject/{subjectId}` и инициализирует выбранную группу/задачу.[6]
- Изменение выбранной группы подставляет её имя в `groupNameDraft`, аналогично для задач и `taskNameDraft`.[6]
- Создание/редактирование/удаление групп:
  - `POST /api/theory/task-groups` c `name`, `is_single`, `subject_id`.
  - `PUT /api/theory/task-groups/{group_id}` (сохранение имени и флага `is_single`).
  - `DELETE /api/theory/task-groups/{group_id}` с последующим перерасчётом выбранной.
- Задачи внутри группы:
  - `POST /api/theory/task-groups/{group_id}/tasks` — создать задание.
  - `PUT /api/theory/tasks/{task_id}` — сохранить имя и группу.
  - `DELETE /api/theory/tasks/{task_id}` — удалить.
- Привязка теорий к задаче:
  - Чекбоксы по списку `theories` из `FormApp`.
  - `PUT /api/theory/tasks/{task_id}/theories` с `theory_ids` в нужном порядке; порядок сохраняется на бэке через `TaskTheoryAssociation.order`.[6]

Группы можно сворачивать/разворачивать; список `expandedGroupIds` хранит идентификаторы раскрытых групп.[6]

## Тренажёры

Тренажёры реализованы как независимые модули, которые получают данные (списки слов) из локальных файлов `data/*.js` и управляются через два универсальных хука: `useWordTrainer` и `useLetterTrainer`.[10][11][7][8][9][23]

### Общая инфраструктура тренажёров

#### Вспомогательные утилиты и пагинация

- `trainerUtils.js`:
  - `PAGE_SIZE = 50` — размер страницы для пагинации.
  - `shuffleArray` — перемешивание массива слов.
  - `loadState`/`saveState` — чтение/запись состояния тренажёра в `localStorage` (JSON).[29]

- `useTrainerPagination`:
  - Принимает `items`, функцию `isPageDone(slice)` и колбэк `onPageComplete`.
  - Считает `currentPage`, `start`, `end`, `totalPages` и `pageSlice`.
  - Следит, чтобы попап «страница завершена» показывался один раз, используя `shownPages` (Set страниц).[22]

#### Хук `useWordTrainer`

Используется там, где каждая единица — целое слово с одним результатом (стресс, слитно/раздельно):[11][8][23]

- Состояние: `words`, `wordResults`, `stats { total, correct, wrong }`, флаги попапов и выхода.[11]
- Инициализация:
  - Пытается загрузить сохранённое состояние из `localStorage`.
  - Если найдено — нормализует формат (поддержка старых версий, где слова были строками).
  - Иначе вызывает `_reset()`: перемешивает `rawData`, нормализует в объекты `{ question, answer }`, создаёт пустые `wordResults` и статистику.[11]
- `resetPage()` — сбрасывает результаты только на текущей странице, корректируя статистику и разрешая повторный показ попапа для страницы.[22][11]
- `updateResult(absIndex, newResult, isCorrect)` — обновляет запись для слова, увеличивает `correct`/`wrong` и возвращает обновлённый массив.
- `collectPageMistakes()`/`collectAllMistakes()` — собирают список слов с неправильным ответом для показа в попапах.[11]
- `_triggerExit()` — если есть ошибки, открывает попап «показать ошибки перед выходом», иначе вызывает `onExit`.[11]
- Интеграция с Telegram:
  - Подписывается на `window.Telegram.WebApp.onEvent('backButtonClicked', handleBack)`.
  - В `handleBack` сначала закрывает активные попапы, затем листает страницы назад или инициирует выход через `_triggerExit()`.[11]

#### Хук `useLetterTrainer`

Используется для задач, где проверяются отдельные буквы (приставки, словарные слова):[7][9][10]

- Состояние: `words` (объекты с `original`, `lower`, `check`), `letterStates` (по массиву для каждой буквы, которую нужно ввести), `stats` по буквам, текущие индексы `currentWord`/`currentLetter` и все флаги попапов/выхода.[10]
- `_reset()`:
  - Применяет `parseWord` ко всем словам из `rawData`.
  - Перемешивает массив, создаёт `letterStates` c записями `{ done: false, correct: null, input: '' }` на каждую проверяемую букву.
  - Считает общее количество букв `total` как сумму `word.check.length`.[10]
- `resetPage()` — по странице пересобирает `letterStates` из `words[i].check`, корректируя статистику и позволяя попапу снова появиться.[10][22]
- `focusFirstEmpty()` — находит первую незаполненную букву на текущей странице и выставляет соответствующие индексы.
- `updateLetterState(wordIndex, letterIndex, newState, isCorrect)` — обновляет одну букву и статистику.
- Механизм сбора ошибок `_collectMistakesFrom` возвращает массив символов с флагом `highlight`, который затем красиво отображается в попапах.[16][10]
- Обработка кнопки «назад» в Telegram аналогична `useWordTrainer`.

#### Общие компоненты тренажёров (`TrainerShared.jsx`)

`TrainerShared.jsx` содержит UI‑компоненты, переиспользуемые всеми тренажёрами:[21]

- `TrainerStats` — отображает прогресс (`answered`, `accuracy`), опираясь на `stats` из хуков.
- `TrainerControls` — панель кнопок (сброс, повтор страницы, ошибки, выход), у всех тренажёров одинаковый UX.[21][16]
- `PageNav` — навигация по страницам (`currentPage`, `totalPages`, `onPrev`, `onNext`).[21][22]
- `MistakesPopup` и `ConfirmPopup` — попапы для просмотра ошибок и подтверждения сброса/выхода.[16][21]

### StressTrainer — тренажёр ударений

`StressTrainer` проверяет правильное положение ударения в слове:[23]

- Данные берутся из `stressWords` (объекты с полем `question`, где ударная буква записана заглавной).[23]
- Использует `useWordTrainer` с `createEmptyResult: () => ({ result: 'none', clicked: [] })`.[23][11]
- `handleVowelClick(absIndex, charIndex)`:
  - Определяет индекс правильной буквы как первую заглавную в `word.question`.
  - Сравнивает с выбранным индексом, обновляет результат через `updateResult`.
- `WordDisplay` разбивает слово на символы, для гласных рендерит `trainer-vowel-slot` с различными классами в зависимости от результата (правильно/неправильно/кликабельно).[16][23]

### PrefixTrainer — ПРЕ/ПРИ

`PrefixTrainer` проверяет выбор буквы в приставке по заглавной букве в исходной строке:[7]

- `prefixWords` — массив слов, где буква приставки, подлежащая выбору, обозначена заглавной буквой.[7]
- `parseWord` возвращает `{ original, lower, check }`, где `check` — индексы заглавных букв.[7]
- Использует `useLetterTrainer` с этой функцией `parseWord`.
- `handleChoice(letter)`:
  - Проверяет текущую букву, сверяя введённую `letter` с `correctChar` по индексу из `check`.
  - Через `updateLetterState` сохраняет результат и продвигается к следующей букве/слову, перескакивая уже полностью решённые слова.[10][7]
- Отрисовка слова в `WordInput` использует `trainer-letter` и, при ошибках, показывает исходный символ над/под введённой буквой.[7][16]

### DictionaryTrainer — словарные слова

`DictionaryTrainer` полностью повторяет паттерн `PrefixTrainer`, но с другим источником данных и более сложной логикой фокуса на активном слове:[9][10]

- `dictionaryWords` — массив слов с заглавными буквами там, где нужно вводить орфограмму.[9]
- Использует `useLetterTrainer` с похожей реализацией `parseWord`.[9][10]
- Поддерживает ввод через скрытый `input` (`inputRef`) и автоматически скроллит активное слово в центр видимой области (учитывая высоту виртуальной клавиатуры через `window.visualViewport`).[9]

### SpellingTrainer — слитно / раздельно

`SpellingTrainer` проверяет написание выражения слитно или раздельно:[8]

- Данные `spellingWords` содержат строки с пометками в скобках, которые разбираются через `parseParts`.
- `resolveWord(str, correct)` собирает итоговое слово либо слитно (`correct === 'solid'`), либо с пробелами (`'separate'`).[8]
- Использует `useWordTrainer` c `createEmptyResult: () => ({ result: 'none', chosen: null })`.[8][11]
- `handleChoose(option)` устанавливает результат и выбирает следующее незавершённое слово на текущей или следующей странице.
- `SpellingItem` визуально подчёркивает область выбора, пока пользователь не ответил; после ответа показывает верный вариант и окрашивает элемент в зелёный/красный.[8][16]

## Интеграция с бекенд‑API

Фронтенд напрямую использует описанные в backend‑документации REST‑эндпоинты без дополнительных абстракций:

- `GET /api/theory/all_theory_dop_info` — справочники предметов и типов теории (FormApp).[3]
- `GET /api/theory/all_theory_for_subject/{subject_id}` — список теорий по предмету.[3]
- `GET /api/theory/get_theory/{theory_id}` — загрузка теории с деревом блоков (и для пользовательского попапа, и для формы).[2][3]
- `POST /api/theory/` — создание новой теории (FormApp).[3]
- `PUT /api/theory/{theory_id}` — обновление типов теории.[3]
- `POST /api/theory/{theory_id}/blocks` — создание блока теории с учётом `parent_id` и `order`.[3]
- `PUT /api/theory/blocks/{block_id}` — обновление блока (тип, контент, порядок, родитель).[3]
- `DELETE /api/theory/blocks/{block_id}` — удаление блока.[3]
- `GET /api/theory/get_tasks_theory_for_subject/{subject_id}` — загрузка групп заданий и их связей с теориями.[6]
- `POST /api/theory/task-groups` / `PUT` / `DELETE` — CRUD по группам заданий.[6]
- `POST /api/theory/task-groups/{group_id}/tasks` / `PUT /api/theory/tasks/{task_id}` / `DELETE /api/theory/tasks/{task_id}` — CRUD по заданиям.[6]
- `PUT /api/theory/tasks/{task_id}/theories` — полная замена связей задания с теориями с сохранением порядка.[6]

Все запросы выполняются через нативный `fetch` с `Content-Type: application/json` там, где ожидется JSON‑тело.[2][6][3]

## Интеграция с Telegram WebApp

Интеграция с Telegram WebApp явно выражена в тренажёрных хуках:[10][11]

- Оба хука (`useWordTrainer`, `useLetterTrainer`) получают объект `window.Telegram?.WebApp`.
- Подписываются на событие `backButtonClicked`, реализуя следующий сценарий:
  - Если открыт попап ошибок/подтверждения выхода, он закрывается.
  - Иначе, если текущая страница > 0, происходит переход на предыдущую страницу.
  - Иначе инициируется `_triggerExit()`, который либо показывает финальный попап с ошибками, либо вызывает `onExit` (обычно возвращение в основной экран приложения).[10][11]

Это делает тренажёры «нативными» для UX Telegram и согласованными с системной кнопкой «Назад».

## Локальное хранение и продолжение прогресса

Фронтенд активно использует `localStorage`:

- В `App.jsx` — функции `saveInfo`/`getInfo` для хранения пользовательских настроек (например, выбора предмета/темы или состояния тренажёров).[1]
- В тренажёрах:
  - `trainerUtils.loadState`/`saveState` читают/пишут JSON‑состояние.
  - `useWordTrainer` и `useLetterTrainer` сериализуют слова, результаты, статистику и текущую страницу/индексы при каждом изменении.
  - При `reset` удаляют соответствующий ключ из `localStorage`.[29][11][10]

Это позволяет ученику вернуться в тренажёр и продолжить с того же места, даже если WebApp был закрыт.

## Best Practices и особенности реализации

- **Чёткое разделение пользовательского и административного интерфейсов** через разные entry‑points (`App.jsx` и `FormApp.jsx`), что облегчает разное окружение (Telegram WebApp для учеников и отдельная страница для админа).[30][18][1][3]
- **Минимальная связка с фреймворками на уровне домена** — логика работы с деревом блоков (`flattenBlocks`, коллекция детей, порядок `order`) находится в React‑коде, но опирается на те же инварианты, что и доменный слой бекенда.[3]
- **Полная поддержка иерархических блоков** на фронте: дерево `BlocksTree` синхронно отображает структуру `TheoryBlock` из бекенда, а `BlockEditor` не ломает формат переносов строк, важный для разметки теории.[5][4][3]
- **Единый дизайн‑язык** для теоретических блоков, попапов и тренажёров через общие CSS‑токены и перезапользование анимаций (`fadeIn`, `slideDown`).[14][16][12]
- **Продуманный UX тренажёров**:
  - Пошаговая пагинация с размером страницы 50.
  - Автоматический показ попапа после прохождения страницы.
  - Просмотр ошибок текущей и всех страниц.
  - Мягкий выход с предложением посмотреть ошибки, если они остались.
  - Поддержка аппаратной/telegram‑кнопки «Назад».[29][22][23][8][9][7][10][11]
- **Адаптивность**: медиазапросы в CSS подстраивают размеры элементов (попапы, кнопки, текст) под мобильные экраны, что критично для Telegram WebApp на смартфонах.[16][12][13]
